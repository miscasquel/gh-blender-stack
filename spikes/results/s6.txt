# S6 — curves, points, SubD and Brep through the product conversions

2026-10-12, live in Rhino 8 under wine via the spike `.gha` (`check=s6`).
Driver: `spikes/s6/driver.py` (writes its raw transcript to `s6-run.txt`);
checks: `spikes/s6/S6Checks.cs`.

**Result: PASS, and then a deeper fix.** The first live run (transcript below)
passed every check but exposed two real-world failures in the GUI:

1. **Circles and other curve goos never arrived.** `Stage Out` matched only
   `GH_Curve`; the Circle component emits a `GH_Circle`, which has no
   `CastTo<Curve>` and fails `GH_Convert.ToCurve(Primary)`. Dispatch now
   unwraps the struct-backed goos (`GH_Circle`, `GH_Arc`, `GH_Line`,
   `GH_Rectangle`) and falls back to the goo's own cast.
2. **Every rational curve arrived distorted (arcs looked like parabolas).**
   Rhino stores *homogeneous* control points; the wire (and Blender) carry
   *Euclidean* coordinates plus a weight. Both directions mixed the two.

The conversion was then rebuilt around a construction that is exact by
definition, instead of inspecting knot patterns:

- `MakePiecewiseBezier` (lossless) makes every span a single rational Bezier.
- Blender holds a single span exactly as a NURBS spline whose order equals its
  control-point count, for any order 2..6, weights included.
- So **each span travels as one wire curve**, and circles, ellipses, and arcs of
  any angle are exact — no fitting, no warnings. Only curves the decomposition
  cannot carry (degree above 5, periodic) are fitted with cubic Beziers inside
  the 0.1 mm budget and counted as approximated (D3).

## Local validation with the real kernel (rhino3dm + Blender)

| Direction | Max radius error, circle radius 5 |
|---|---|
| Rhino piecewise spans -> wire -> Rhino (`Point4d(x*w, y*w, z*w, w)`) | 1.8e-15 |
| Rhino piecewise spans -> wire -> Blender (`sections_to_curve`) | 4.8e-07 (f32 quantisation) |

Blender layer B covers the same wire form headlessly
(`test_rational_quadratic_spans_make_a_circle`, 42 tests).

## Live confirmation

The operator's graph (Circle and Ellipse components into Stage Out, Blender
session on the other side): circles, ellipses, and arcs of any angle arrive
correctly after the fix — "works like a charm". The earlier parabola and the
dropped-circle symptoms are gone.

## What the first live run already proved (still valid)

- Polyline, points, SubD cage + crease tags, fractional rounding warning, the
  semi-sharp limitation warning, Brep meshing with warning, and the mixed
  orchestration all pass (raw transcript below).
- `Mesh.CreateFromSubDControlNet` returns seam-duplicated control points (19 for
  a 16-point open cage); vertex order is not stable across SubD round trips, so
  creases transfer by vertex pair.
