# S9 — attributes ride the geometry; blocks resolve to document definitions

2026-10-16, live in Rhino 8 under wine via the spike `.gha` (`check=s9`).
Driver: `spikes/s9/driver.py` (raw transcript in `spikes/results/s9-run.txt`);
checks: `spikes/s9/S9Checks.cs`.

**Result: both questions are answered.** Attributes ride the geometry (every
check passed, §A). Blocks: no graph-side route can mint a definition with an
identity or an identity-bearing preview, so Stage In will write content-hash-named
definitions into the open document — the fallback probe previews with a valid
bounding box and bakes a real object (§C).

## A. Attributes — PASS on every check

| Check | What it proves |
|---|---|
| `dict_roundtrip: ok` | The geometry `UserDictionary` holds every value kind the wire uses (double/int/bool/byte/string arrays, vectors, points, colours, nested dictionaries) and reads them back. |
| `duplicate: ok` | `Mesh.DuplicateMesh()` carries the dictionary — the operation GH performs when data passes between components. |
| `transform: ok` | A transform keeps it. |
| `goo_duplicate: ok` | `GH_Mesh.DuplicateGeometry()` keeps it — the goo path, not just the geometry path. |
| `curve: ok`, `pointcloud: ok`, `subd: ok` | Duplication carries it for every geometry kind attributes can attach to (the curve case with a transform as well). |
| `bake: ok` | Writing the mesh into the document and reading it back keeps it — the attribute survives a bake round trip. |

So the design's premise holds: an attribute attached to the geometry rides along
with GH's own operations and with the document. The "attributes lost / converted"
reports from the first live sessions are explained by the builds they ran (the
Blender extension predated the attribute code; the plugin could not encode the
response until the `Json` list fix), not by the mechanism. The store is also
pinned by `GhStackAttrTests.exe` in `scripts/test-gha`.

## B. Blocks — construction works, validity does not (without an identity)

`ModelObject.Cast(GH_Mesh)` works graph-side (`IsValid=True`, `Model Mesh`), and
the paired `InstanceDefinition` survives on the reference
(`reference_idef=True`, `reference_duplicate: ok, idef=True`). But a definition
assembled from `ModelInstanceDefinition.Attributes { Objects = ... }` comes back
`IsValid=False` with no `Id`, and its `GH_InstanceReference` is invalid:

- `reference_valid: False`, `reference_bbox: invalid` — no preview geometry;
- `bake_reference: baked=False, object=none, definitions added=0` — baking the
  doc-less reference is a no-op through the API;
- and attempting to bake such a reference raises Rhino's
  **"You are about to bake an invalid block instance"** warning (seen while this
  check ran; §C traces it to the probe's own `bake_reference` call).

The remaining public levers are narrow: `Attribs` and `ReferenceID` are not
public on the definition, so a graph-side definition cannot be given an identity
or content through the constructor path. Round 2 ran `definition_cast` and the
`doc_reference_*` probes 2026-10-16; §C below carries the result and the
decision.

## C. Round 2 — the cast route is dead; the document fallback works

Run 2026-10-16, same driver and `check=s9` (`spikes/results/s9-run.txt`):

- `definition_cast: from attributes: IsValid=False, Objects=1, Id=(none)` — the
  public `Cast` from a `ModelInstanceDefinition.Attributes` returns a definition
  that is still invalid and has no identity.
- `reference_cast: IsValid=False, whyNot=Instance Definition is not valid`;
  `reference_cast_bbox: invalid` — no preview.
- The document fallback passes everything: `doc_reference_valid: True`,
  `doc_reference_bbox: valid: (5, 0, 0) .. (6, 1, 0)`,
  `doc_reference_bake: baked=True, object=yes` — a definition added through
  `InstanceDefinitionTable.Add`, referenced by a `GH_InstanceReference`, previews
  with a valid bounding box and bakes to a real object.

**Decision: Stage In writes content-hash-named definitions into the open
document** (for example `GHStack <hash>`), reuses them across solves, and
references them per instance. The graph-side route is dead for the product: it
cannot mint an identity, and even a doc-less reference cannot bake (round 1's
`bake_reference: baked=False`). Realized geometry remains the fallback when
there is no open document.

*(Superseded by §D, same day: the graph-side route only needs a **Name**. A
named attributes-built definition is valid, previews and bakes, and that is the
route the product now uses.)*

Two footnotes for the record:

- The probe only tries `Cast(objects)` / `Cast(object)` when `Cast(attributes)`
  returns null; it returned non-null-but-invalid, so those two forms were never
  exercised. They would not change the decision — a graph-side definition still
  cannot bake.
- The "You are about to bake an invalid block instance" dialog that appears
  during the run comes from the probe itself: `bake_reference` bakes the invalid
  doc-less reference through GH's bake path, which raises the warning and then
  declines (`baked=False, object=none`). No product component is involved.

## D. Round 3 — instances, live, graph-side (the route the components use)

Rounds 3 and 3b–3f ran the instances path through the spike checks
(2026-10-16). Two product bugs, one probe bug and one design change came out:

- **Round 3, document route**: `StageGeometry.Build` wrote document definitions
  and every check passed except `instances_attribute` /
  `instances_emit_attribute`: attributes were attached *after*
  `InstanceDefinitions.Add`, which stores its own copy of the geometry. Fixed:
  attach first (still true for the document fallback).
- **Round 3b, nested**: the emit path read nothing for a nested block because a
  block-instance `ModelObject` refuses `CastTo<InstanceReferenceGeometry>`. The
  document copy worked; it was later replaced by the goo route below.
- **Round 3d (owner's pointer)**: a definition built from
  `ModelInstanceDefinition.Attributes` **with a Name** is valid, previews
  (`named_reference_bbox: (5,0,0)..(6,1,0)`) and bakes (`named_bake: baked=True`)
  with **no document write** (`named_document_added: none`). Round 2 set
  `Objects` only, hence the earlier "graph-side is dead". `ToModelData()`
  returns the definition itself (`named_model_data: ModelInstanceDefinition`).
- **Round 3e, graph-side facts**: `ModelObject.Cast(GH_InstanceReference)` makes
  the "Model Block Instance" object that the Block Definition component takes
  through its `Objects` input — nesting works graph-side; the parent previews
  and bakes with the child in place (`graph_reference_bbox` / `graph_bake`
  `(0,0,0)..(1,1,2)`); the bake materializes parent and child once, so repeat
  bakes reuse them (`graph_bake_twice: definitions added=2` after two bakes).
  `nested_child_transform` must read `Value.Xform`; `ModelTransform` is a
  display accessor and read `z=0` here even though the bake honored the offset.
- **Round 3f, product switch**: Stage In/Out now build **named graph-side
  definitions**. Final run, flat and nested: `instances_document_added: none
  (materialized at bake)`, `instances_definition: 'S9 Quad', IsValid=True`,
  `instances_attribute: load=FLOAT/POINT`, `instances_bake`/`nested_bake:
  baked=True`, `nested_bbox`/`nested_bake` `(0,0,0)..(1,1,2)`,
  `nested_baked_definitions: 'S9 Parent', 'S9 Child'`, and the emit round trip
  unchanged (`instances_emit_rows: 2 rows`, `instances_emit_transform: 5,0,0
  preserved`, `nested_emit_rows: parent row names the child`).

The probe bug: the nested synthetic frame wrote its matrix with the translation
in the last row; the wire pins it in the fourth column (elements 3, 7, 11), so
the check placed nothing and two runs looked like a product bbox limitation.
Fixed; `checks_revision: 3f` marks the build that carries the trace keys
(`nested_row_transform`, `nested_child_transform`).

**Decision (supersedes §C's document route): definitions are named graph-side
`ModelInstanceDefinition`s**, exactly as GH's Model Block Definition/Instance
components build them. No document definitions are created at solve time; Rhino
materializes the blocks on first bake and reuses them. `GHStack <hash>` remains
only as the fallback name for a definition Blender did not name.

The "invalid block instance" dialog that appeared during every run was the
probe's own round-1 `bake_reference` call on the invalid doc-less reference.
That bake is now **skipped for invalid references** (the finding is recorded
above), so a warning-free run is the standing control that nothing else raises
it.

## Note on timing

Round 1's reply took 37.8 s: the checks run on the Rhino UI thread
(`RhinoApp.InvokeAndWait`), and that call queued behind an active Grasshopper
solve on the user's canvas (the S9 run happened while a live loop was solving).
Round 2, with the canvas idle, replied in 8.4 s. Not a defect in the checks; the
probe is UI-thread-bound by design.
