## Where it stands

**The instances feature works end to end and is owner-verified live** — a
Blender scene with an "Instance on Elements" modifier round-trips through
Stage In → Stage Out → visible instances, and **editing the instanced geometry
updates both sides**. The last "still nothing" report was canvas wiring on the
owner's side (Stage Out's `G` input), not a product bug.

**Nested blocks now work both ways** (2026-10-17, after the live report):
GH → Blender builds each definition's prototype chain recursively — nested
placements arrive through `Transform` nodes, so a parent's rows instance the
nested content with it (single and two-level covered; a Cycles check draws
two quads). Blender → GH accepts the shapes Blender's own instancing makes:
an **empty that instances a collection** crosses as a nested row, and a
**child collection's members** join the parent's definition (Blender instances
both as one thing).

## 1. Two facts that cost today's hunt — do not re-derive them

1. **A referenced collection's members are references too.** The prefix
   revision listed only the collection; a member's geometry edit never moved
   the revision, the memo won, and neither side updated. Fixed in `aa630a3`
   with layer B tests that capture the engine's send before and after such an
   edit (collection member and object source).
2. **`sha256:e3b0c442…` is the hash of nothing.** Stage Out with an empty
   `Geometry` input answers exactly that, and Blender then clears the stage
   output — so "nothing arrives in Blender" reads as: check Stage Out's
   `Sent` / `Hash` / `Status` and Stage In's header (`ok · N blocks`) first.
   One look splits sender, canvas and receiver.

## 2. Debug recipes that paid off (keep)

- **The owner's scene, headlessly.** Open the autosave / `quit.blend` with
  `bpy.ops.wm.open_mainfile`, enable the add-on, then call
  `engine._prefix_sections(obj, record, stage)` — it prints exactly what
  Blender would send (definitions, rows, hash). Two live bugs were isolated
  this way without touching the running session.
- **The responses GH actually sent.** Decode
  `~/.local/share/gh-stack/cache/<stack_id>/<stage_key>/*.bin` with
  `codec.decode_frame`; the newest by mtime is the last answer, and its header
  carries `definitions`, counts, warnings and `out_hash`.
- **Force a fresh exchange:** Push in the Blender panel (clears the caches and
  takes a new rid).
- **Prove drawing, not just evaluation:** a tiny Cycles CPU render with lit
  pixels counted (references drew 0; geometry copies 1613).

## 4. Working notes

  Rhino restart; changed add-on code a Blender restart. Build/deploy:
  `grasshopper/build/build-gha.sh` → `grasshopper/deploy/deploy.sh` →
  `scripts/check-deployed`; spike: `spikes/s1/build.sh` →
  `spikes/s1/deploy.sh` (compiles `Instances.cs`); extension:
  `scripts/build-extension` + `scripts/install-extension`.
- Layer B ports: `test_instances.py` uses 9151. To realize instances in a
  headless test, add a temporary Realize Instances modifier after the stage;
  to check *drawing*, render and count pixels.
- **Nesting shapes, one line each:** Blender's "empty with
  `instance_collection`" crosses as a **nested row** (the placement); a
  **child collection's members** join the parent's definition (Blender
  instances both as one thing). On the way back, each definition's prototype
  chain is recursive — nested placements come in through `Transform` nodes —
  so a parent's rows instance the nested content with it.
- The engine-update tests (`EngineUpdateTests`) bump the epoch keys the
  depsgraph handler would name — handlers do not fire under `-b` — so they
  test the plumbing, not the GUI's tagging.
- Stage In's component message shows `ok · N blocks`; keep it when touching
  the component.
