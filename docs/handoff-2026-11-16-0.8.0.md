## 2. Mission for 0.8.0

Ship **0.8.0 “Architecture, speed, truth”**:

- No new user-facing features.
- Split the god modules behind owned interfaces, without growing the production
  codebase net.
- Make performance a real regression gate, not a smoke test.
- Remove dead code, legacy shims and archival noise.
- Make docs/CI/release artifacts truthful and reproducible.
- Complete the verification matrix: fuzz, coverage, scale, soak, native
  acceptance where the environment allows.

Target: every module ≥ 8.5/10, with no critical/major findings on a fresh audit.
The remaining accepted exceptions must be written down, not ignored.

## 3. Non-negotiable quality rules

1. **One owner per invariant.** Frame validity, topology apply, stage state,
   lifecycle, registry ownership and definition identity each have one owner.
2. **No god modules.** A module has one reason to change. Size is a review
   trigger, not a hard line-count gate; splitting files without removing
   responsibility is not a fix.
3. **No net production growth without subtraction.** Every W7 seam PR must
   either keep production LOC flat or remove equivalent duplication/dead code.
   Do not count tests/docs/vendor as production.
4. **No dead code, test-only production API, or un-owned shim.** A compatibility
   shim needs an ADR, a migration test and a removal version. Delete what has
   none.
5. **No performance regression.** Add a p50/p95 baseline gate before moving hot
   paths. A regression above **5% on any metric fails**. A regression of 0–5%
   is allowed only when the same task reports a quantified offsetting gain
   (another benchmark metric, code-size reduction, test/runtime, or a
   documented correctness/simplicity benefit) and the audit accepts the trade.
   A regression without an offsetting gain is a failure, not a trade-off.
6. **No silent loss.** Every approximate/dropped input produces a visible
   stage warning; malformed peer input produces a typed error.
7. **Behavior-preserving refactors.** Characterization tests land before a
   move. Bug fixes get a regression test that fails before and passes after.
8. **Tests are not the metric to cut.** Consolidate duplicate tests; do not
   remove coverage to make a line target.
9. **Docs are claims with owners.** No stale test counts, transport, paths,
   ADR statuses or release links.
10. **C# 5/Mono** remains the production constraint unless the .NET framework
    spike has a written go decision.

## 4. Working method (follow this exactly)

You are the **orchestrator**. The user expects:

1. **One subagent per task**, sequentially.
2. The subagent implements, tests and reports. **It does not commit.**
3. You audit the result against §3 and the task acceptance. Inspect the diff,
   production vs tests LOC, tests, benchmark delta, docs truth and residue.
4. If anything is wrong, send the task back with specific findings. Do not
   commit a partial or unverified task.
5. Commit only after the audit passes. One commit per accepted task, with the
   task ID and invariant/test evidence in the message.
6. Do not start the next task until the current one is committed.
7. At the end, run the full gate and the release process.

Each task report must include:

- files changed and why;
- **production vs test vs docs/bench LOC**;
- exact commands/results, test counts and gate runtime;
- benchmark before/after for any hot path;
- any accepted deviation/known gap;
- no debug prints, no test-only production hooks, no dead code.

**Never run the full gate and benchmarks concurrently.** That caused a false
failure in 0.7. Run `scripts/check-all` alone, then benchmarks.

**No branching.** This is a single-developer repository: work directly on
`main`. Do not create feature branches or worktrees for 0.8.0. Keep the 0.7.0
tag untouched; commit each accepted task on `main`; tag only at the release.

```bash

scripts/test-blender           # layer B
scripts/test-gha               # C# full local suite
scripts/test-gha --codec-only  # no Rhino needed
scripts/bench                  # budgets; add baseline check in T1
scripts/check-docs             # version/transport/fixtures/paths
git diff --check
uvx ruff@0.17.2 check .
```

Build/install for manual testing:

```bash
scripts/build-extension
scripts/install-extension
grasshopper/build/build-gha.sh
grasshopper/deploy/deploy.sh
scripts/check-deployed
```

Grasshopper scans `Libraries` only at startup; restart Rhino after deploy.
Blender must be restarted to load a new extension.

## 6. Task order

### T1 — Baseline, performance gate, code health (start here)

**Goal:** make 0.8 measurable before any refactor.

- Create a clean 0.8 benchmark baseline from 3 solo runs
  (`benchmarks/results/2026-11-16-linux.json` or equivalent).
- Add `bench.py --check-baseline`: compare per-scenario p50/p95 to the stored
  baseline. **Any metric over +5% fails.** A 0–5% regression is accepted only
  with a quantified offsetting gain recorded in the same task report; no
  unoffset regression is allowed.
- Add a performance ledger: baseline, each task's measured delta, the offsetting
  gain (if any), and the approved decision.
  Include pipeline, in-place apply, instance repeat, playback, roundtrip.
- Add a C# parameter/schema microbenchmark (schema publishing and
  `FormatDouble`/`ParamValues` are not in the Blender matrix).
- Add a code-health report (not a hard gate): production LOC by module,
  largest functions/classes, duplicated dispatch tables, dead exports,
  dependency edges, test counts.
- Wire the baseline check into `scripts/check-all` and CI; add a deliberate
  regression test that proves the check fails.
- **Acceptance:** `check-all` green; baseline comparison fails on a temporary
  6% regression and on any >5% regression; no production behavior change.

### T2 — Subtraction before refactor

**Goal:** remove noise before moving code.

- Delete/archive `spikes/`, `plan-gh2.md`, the stale 2026-11-13 handoff,
  `build-core.sh`, dead parameter/attribute exports, duplicate
  `PROTOCOL_VERSION`, unused icons, stale shims and unused `.gitkeep`s.
- Decide the 21k-line vendored `websockets` tree: official wheel only, or
  explicitly dev-only with license completeness. Do not leave it ambiguous.
- Remove old local artifacts only if untracked; do not delete user data.
- **Acceptance:** no behavior change, `check-all` green, production and total
  tree smaller, report lists every deletion/archival decision.

### T3 — Characterization tests for the seams

**Goal:** pin behavior before W7.

- Add/complete tests for `geometry_io`, the Blender engine hub, `GhLink`, and
  `Instances` covering the public behavior and failure modes the refactor will
  move.
- No production edits in this task.
- **Acceptance:** tests pass on the unchanged code; the map names every seam
  and the tests that protect it.

### T4 — `geometry_io` package split

- Split into mesh/attributes/curves/points/instances/dispatch modules behind a
  small facade.
- Table-drive per-kind read/write dispatch; remove copy-paste color/curve/
  attribute loops.
- Keep the topology-token fast path and its benchmarks intact.
- **Acceptance:** one responsibility per module; no production net growth;
  full gate; in-place benchmarks unchanged (±5%).

### T5 — Blender engine object

- Replace the package-global hub/`sys.modules[__package__]` pattern with an
  `Engine` object and per-stage runtime records.
- Remove the 157-name `__all__` and extraction residue.
- Keep UI/ops import surfaces stable or migrate them explicitly.
- **Acceptance:** no global mutable registry outside its owner; lifecycle/
  playback/bake tests unchanged; full gate.

### T6 — `GhLink` split

- Split into `StageRegistry`, `LinkConnection`, `RequestScheduler`,
  `ProtocolHandler`, `Publication`, `StageSlot`/`HeldFrame`.
- Preserve document isolation, UI-thread marshaling, caps/`blocks/2`,
  transport behavior, and stage-key conflict semantics.
- Move tests with the code; keep `LinkTests` as integration proof.
- **Acceptance:** no GH/Rhino calls on socket threads; single-document and
  two-document tests green; no behavior change.

### T7 — `Instances` split and table-driven conversion

- Split Build/Emit/definition writer; add Point/curve-attribute gaps only if
  required to keep the existing contract.
- Table-drive `Conversion`/`Attributes` per-kind dispatch; remove repeated
  curve appenders and five-way type switches.
- **Acceptance:** single-part/multi-part/nested/attribute round trips unchanged;
  native Rhino probe green; production LOC down or flat.

### T8 — Performance follow-through

- Investigate playback +7–9%; fix or document an accepted exception.
- C# `Section` owner/offset/length views; fewer mesh copies; publication
  dirty flags; `ActiveDoc`/`Find` cleanup; schema/param allocation.
- Blender `ensure_group` per-pass signature cache; avoid full `bpy.data`
  scans; direct array writes; linear stage/param grouping.
- **Acceptance:** p50/p95 within 5%; any 0–5% regression must name its

### T9 — Lean/docs/CI/build/framework

### T10 — Verification

- Fuzz frame mutators (10k/language) with classified failures only; geometry/

- Scale: 200 stages, 100k triangles, 10k instances.
- 1-hour churn soak (stage add/delete/rename/undo, playback, bake, reconnect).
- Native Windows/Rhino acceptance and chain playback/bake where available.
- **Acceptance:** the suite proves invariants, not only happy paths; a new bug

- **Acceptance:** release page and installed artifacts match the tagged commit.

- [ ] No debug prints, test-only production counters, dead code, unused shims.
- [ ] One owner for the changed invariant; no duplicated dispatch.
- [ ] New behavior has a regression test; refactor has characterization proof.
- [ ] Hot-path changes have before/after p50/p95 and no >5% regression; any
      0–5% regression names a quantified offsetting gain approved at audit.

- [ ] `git diff --check`, ruff, docs check pass.
- [ ] Protocol/`out_hash`/fixtures unchanged unless the task explicitly changes
  them.
- [ ] Docs describe the behavior that actually shipped.
- [ ] Commit message names the task and the invariant/test evidence.
